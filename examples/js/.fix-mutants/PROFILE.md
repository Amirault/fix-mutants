## Environment setup

`npm install` (Stryker is a dev dependency: `npm i -D @stryker-mutator/core` plus the runner plugin for your test framework, e.g. `@stryker-mutator/jest-runner`).

## Mutation command

Run from the folder holding `package.json` and the Stryker config (paths in `--mutate` are relative to it):

```bash
cd examples/js
npx stryker run --mutate "src/<relative/path/to/file>" --reporters json,clear-text
```

- Raw report: `examples/js/reports/mutation/mutation.json` (default `jsonReporter.fileName`).
- Keep that file until `verify` has run; copy the final JSON outside the worktree.

## Caller search

```bash
rg -n -g '*.{js,jsx,ts,tsx,mjs,cjs}' -g '!node_modules' -w '<Member>' . | rg -v 'examples/js/test/'   # production + tooling
rg -l -g '*.{js,jsx,ts,tsx,mjs,cjs}' -g '!node_modules' -w '<Member>' . | rg 'examples/js/test/'              # tests
```

Search the exported name and re-exports (`index.ts` barrels). Implicit consumers: dynamic `require`/`import()`, route tables, dependency-injection containers.

## Build-forced edits in moves

Moving a module can force import path changes in callers and, for TypeScript, `tsconfig`/lint-driven edits (strict null checks, unused imports). Allowed: import path swaps and honest type annotations. List each in the commit body.
