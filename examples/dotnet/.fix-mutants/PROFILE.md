## Environment setup

Install the tool from the manifest: `dotnet tool restore` (add it with `dotnet new tool-manifest && dotnet tool install dotnet-stryker` if `.config/dotnet-tools.json` is missing).
Keep the local version and CI's identical.

## Mutation command

Run from the **test project directory** (`examples/dotnet/tests/Shop.Tests`), never from a folder holding a solution file (Stryker would switch to solution mode and run every test project):

```bash
cd examples/dotnet/tests/Shop.Tests
dotnet stryker \
  --project Shop.csproj \
  --test-project Shop.Tests.csproj \
  --mutate "**/<relative/path/to/File>.cs" \
  --reporter cleartext --reporter json \
  --break-at 0
```

- Pass bare project file names, not relative paths.
- Raw report: `examples/dotnet/tests/Shop.Tests/StrykerOutput/<timestamp>/reports/mutation-report.json`. Never delete `StrykerOutput/` before `verify` has run; copy the final JSON outside the worktree.
- After the final run delete the production and test projects' `bin`/`obj` (stale mutant binaries), then run a clean build and the unit tests.

## Caller search

```bash
rg -n -g '*.cs' -g '!**/bin/**' -g '!**/obj/**' -w '<Member>' . | rg -v 'examples/dotnet/tests/Shop\.Tests/'   # production + tooling
rg -l -g '*.cs' -g '!**/bin/**' -g '!**/obj/**' -w '<Member>' . | rg 'examples/dotnet/tests/Shop\.Tests/'              # tests
```

Extension methods are called without their type: search the method name. Implicit consumers: DI registrations, reflection, serialization, generated record members.

## Build-forced edits in moves

Moving a file to another project can break the build through rules the old location muted (nullable context, analyzer config, unused usings under `TreatWarningsAsErrors`). Allowed: namespace/using changes, and annotations the nullable context forces (`string?` where it really returns null — never `!`). List each in the commit body.
